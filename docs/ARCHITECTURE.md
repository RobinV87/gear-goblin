# Architecture

Milestone 1A is a browser application. React renders the interface; device validation and the repository contract are separate from presentation. The browser adapter uses Dexie over IndexedDB, with UUID keys and a versioned schema. Version 2 adds device-related firmware, storage, accessory and modification records; version 3 adds one optional image per device; version 4 adds local appearance and view preferences; deleting a device and its related records uses one transaction. No network service is involved at runtime.

The future Android adapter must implement the same application-facing contract using native SQLite, with explicit migrations, transactions and tested import/export. Browser and native storage are separate physical databases: moving data between them needs a deliberate backup/migration workflow. Browser storage can be evicted or cleared. Version 2 backups include preferences; version 1 backups remain readable and restore default preferences. Backups are ZIP files with a strict JSON manifest and separate image files. Imports accept only this application’s uncompressed ZIP format, enforce path, size, checksum, schema, unique-ID and reference checks, and replace the entire collection in one transaction after confirmation. Duplicate IDs are reported in the preview. Backups are unencrypted; the archive limit is 50 MB and images are limited to 5 MB each. Browser and future native file flows need separate verification.

Navigation currently uses local UI state. Native back handling, lifecycle, permissions, file access, accessibility refinement and device testing remain Android work. Appearance preferences are stored in the browser database; system appearance and reduced-motion accessibility settings remain supported. No studio-wide framework is required; proven patterns or components can later be extracted into independent packages when another product actually needs them, without tying products to a monorepo or backend.
